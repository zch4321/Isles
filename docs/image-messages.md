# 图片消息

日期：2026-10-29。

## 使用

Web 输入框支持选择、粘贴和拖放图片。图片先上传，发送时可以只发图片，也可以配上文字、回复和提及。草稿按会话保留，上传或发送失败时可重试；发送成功只清除本次提交的内容。聊天中可放大预览或查看原图。

Agent 使用 `send_message` 的 `imagePaths` 参数发送本地图片，例如：

```json
{
  "channelId": "private",
  "body": "这是生成的设计稿。",
  "imagePaths": ["F:\\projects\\demo\\design.png"],
  "clientId": "design-image-1"
}
```

服务在发送时保存图片快照，原文件后续变化保留已发布图片。相同来源与 `clientId` 的重试复用消息序号；修改消息内容时使用新的 `clientId`。

## 图片如何到达 Agent

| 入口               | 图片形式                                 |
| ------------------ | ---------------------------------------- |
| 普通自动回合       | 原生图片内容与频道、消息、图片序号标签   |
| 忙碌时 steer       | 个人工作区内的绝对路径，Agent 按需读取   |
| MCP 收信与历史读取 | 工具返回值中的实际图片内容块，附来源标签 |

普通回合沿用各 harness 的图片协议：Codex 使用本地图片输入，Claude 使用图片内容块，Kimi 和 OpenCode 引用可读本地图片，由原生服务处理，DSH 通过原生附件服务构造图片引用。通用 ACP 按声明的图片输入能力发送。

模型明确缺少图片输入能力时，消息保持排队。用户选择支持图片的模型并恢复 Agent 后，继续投递原消息。原生服务自身的图片处理遵循对应模型配置。

## 格式与存储

- 每条消息最多 4 张，每张上限 10 MiB。
- 支持静态 PNG、JPEG、WebP 和 GIF。动画图片使用 GIF 或 WebP，最多 100 帧。
- 单边最大 8192 像素，所有帧合计最多 4000 万像素。上传会校验实际文件类型、文件结构和完整解码。
- 原图保存在 Isles 数据目录，Agent 从其个人、共享或附加工作区导入图片；完整访问沿用 Agent 配置。
- 每位 Agent 获得经过校验的个人工作区副本。同一图片可复用该副本，变化时生成新路径。
- 历史图片随消息保留；删除会话后，人类继续查看。Markdown 导出包含指向本机服务的图片链接。

`POST /api/channels/:id/images?name=文件名` 上传二进制图片，返回图片 ID 与元数据；`GET /api/channels/:id/images/:imageId` 读取图片。发送消息提交 `imageIds`，返回的 `Message.images` 按发送顺序提供图片信息。

## 投递与并发

每批自动投递及 MCP 读取最多包含 40 MiB 图片，按完整消息切分。超出的消息保持排队或通过分页继续读取。MCP 读取成功并再次检查 Agent 状态和成员关系后确认收信，准备期间由每 Agent 读取锁协调自动投递。

图片准备与原生发送分别记录。停止发生在发送前时保留待处理消息；群成员退出会取消该群的未确认投递，重新加入继续使用之后的消息。执行记录保留原始输入引用，便于查看重试前的执行。

## 验证

覆盖四种图片格式、文件损坏、路径与频道校验、不可变快照、幂等重试、图片分页、MCP 原图返回、steer 路径、停止恢复、群成员变化、并发读取、模型切换重试和历史导出。

五种 CLI 已通过本地模拟模型的原生图片协议验证。DSH 额外验证四张各 10 MiB 的输入及异步子任务生命周期。浏览器验证图片选择、粘贴、拖放、原图预览、Agent 发图、失败重试和跨会话草稿。

`pnpm check` 通过格式、ESLint、全工作区类型检查、生产构建及 706 项测试；1 项 Unix 特有文件名测试在 Windows 跳过。Chrome 完整回归 51 项通过，桌面图片消息、放大预览和手机布局截图已检查。图片准备、原生模型检查、MCP 读取期间的停止恢复与成员变更，以及模型切换后的原图重试均有集成测试。
