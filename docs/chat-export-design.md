# 聊天记录 Markdown 导出

2026-10-09 用户确认格式并授权实现。私聊、群聊以及已删除会话的保留历史均支持导出。

一个会话导出为一个 UTF-8 `.md` 文件。首版导出当前会话的全部正式消息与系统消息，按原消息编号升序排列；私聊、群聊及已删除会话的保留历史使用同一格式。

## 文件头

- 标题：群名，或“与 {Agent 名称} 的聊天记录”。
- 类型：群聊或私聊。
- 导出时间：记录导出快照的时间，包含日期、秒和时区偏移。
- 记录范围：第一条到最后一条消息的时间。
- 消息数：本次导出的消息总数，包含系统消息。
- 发言者：实际发言的用户与 Agent；系统消息统一署名“Isles（系统）”。

时间使用浏览器当前时区，每个时间戳带偏移，例如 `2026-10-09 11:00:00 +08:00`。空会话保留标题、类型、导出时间与“消息数：0”。

## 消息格式

每条消息使用二级标题：`## #编号 · 作者 · 时间`。编号沿用频道内的原消息编号，便于保留回复关系。Agent 作者标明“Agent”，用户署名“用户”。

有回复或提及时，在正文前分别写 `回复：#编号（作者）` 和 `提及：@名称`；没有这些信息时省略对应行。同名 Agent 使用名称加短 ID 区分，沿用项目现有的名称消歧规则；一般消息无需显示 UUID。

正文完整保留 Markdown 源，每行添加引用前缀 `> `。段落、列表、链接、引用和代码块都保留；代码块即使不完整，也保持在该条消息的引用块内。消息之间用 `---` 分隔。标题、作者和单行元数据只转义会改变渲染的字符（反斜杠、反引号、`*`、`_`、`~`、方括号、尖括号、实体引用及标题末尾的 `#`），连字符、句点和括号等常见标点保持原样；正文中的原始名字与文件引用按原样保留。

名字采用导出时的目录名称，与聊天界面一致；模型配置可在历史期间变更，所以消息标题只标明作者身份。执行记录、原生思考和工具活动继续保存在执行详情中。

## 群聊样例

```markdown
# 技术评审

- 类型：群聊
- 导出时间：2026-10-09 11:05:00 +08:00
- 记录范围：2026-10-09 11:00:00 +08:00 至 2026-10-09 11:03:20 +08:00
- 消息数：3
- 发言者：用户、Kimi（Agent）、Codex（Agent）

## #12 · 用户 · 2026-10-09 11:00:00 +08:00

提及：@Kimi

> 请检查这个实现，重点看会话恢复。

---

## #13 · Kimi（Agent） · 2026-10-09 11:02:10 +08:00

回复：#12（用户）

> 找到两处需要调整的地方：
>
> 1. 恢复时重新应用配置。
> 2. 保留原来的 session。

---

## #14 · Codex（Agent） · 2026-10-09 11:03:20 +08:00

回复：#13（Kimi）

> 我补充了回归测试，结果已记录在 [验收文档](docs/kimi-acp-acceptance.md)。
```

私聊只替换文件头，后续消息格式相同：

```markdown
# 与 Kimi 的聊天记录

- 类型：私聊
- 导出时间：2026-10-09 11:05:00 +08:00
- 记录范围：2026-10-09 11:00:00 +08:00 至 2026-10-09 11:02:10 +08:00
- 消息数：2
- 发言者：用户、Kimi（Agent）
```

## 导出行为

入口为会话右上角的“聊天操作”菜单，选择“导出聊天记录”后下载整个会话的 `.md` 文件，包含尚未显示在页面上的历史。下载期间显示进度图标；失败原因显示在对话的操作提示中，可以重新导出。空会话与已删除会话同样可导出。

文件名为 `群聊-技术评审-20261009-110500.md` 或 `私聊-Kimi-20261009-110500.md`，清理文件名中的路径分隔符、控制字符及系统不支持的字符，名称部分限制在 180 个 UTF-8 字节内，按完整字形截断，组合 emoji 与附加符号保持完整。

导出开始时固定消息编号上限和作者目录快照，生成过程中的新消息进入后续导出。首版保持一次点击导出全部；时间范围筛选可以按后续需求增加。

## 实现与验收

`GET /api/channels/:id/export?timeZone=Asia%2FShanghai` 返回 `text/markdown; charset=utf-8`，通过 `Content-Disposition` 提供 UTF-8 下载文件名；浏览器传入当前时区，接口省略时区时使用 UTC。不存在的会话返回 `404`；无法识别的时区返回 `400`，提示中写明该时区并引导检查系统时区设置。

Store 在一个同步只读事务中读取频道、消息上限、完整消息及作者名称。导出独立于历史分页，只读取当前频道，保留已删除作者的名称。格式化完成后浏览器下载 Blob 并释放临时 URL；响应头缺失或无法解析时，文件名使用 `聊天记录.md`。导出不改变投递、未读、事件游标或原生执行状态。

名称消歧与模型消息封装共用 `runtime/names.ts`，Markdown 文件使用可读名称，模型输入继续使用 JSON 引号名称。自动化覆盖完整历史、回复与提及、系统消息、名称转义与常见标点的可读性、短 ID 碰撞、正文代码块、时区与夏令时、便携文件名与按字形截断、快照一致性及只读语义；浏览器覆盖移动端、空会话、下载失败后重试、超过页面上限的私聊及已删除会话。

2026-10-09 验证结果：`pnpm check` 通过（244 项测试通过、2 项跳过），Chrome E2E 21 项全部通过。浏览器从 105 条私聊历史下载完整文件，确认未加载的最早消息也包含在内；空私聊、群聊、已删除 Agent 和群聊、移动端下载及失败重试均通过。
