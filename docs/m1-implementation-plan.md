# M1：Codex 单对象闭环实施计划

> 日期：2026-09-30 · 状态：实现完成，已通过主 agent 独立验收
>
> 主 agent 负责计划、产品决策同步和最终验收；一个活动的 `gpt-6.1-sol / max` 子 agent 负责实现与开发自测。主 agent 已独立检查代码、运行验证并处理发现的问题，结果见 [验收记录](m1-acceptance.md)。

## 1. 本轮已确认的规则

1. 以 Codex app-server 原生 stdio JSON-RPC 接入；本机当前 CLI 为 `0.158.0`，记录实际使用版本。
2. 正式聊天消息统一通过 Isles MCP 发出；原生文本与工具活动属于执行详情，不自动转成聊天消息。
3. 对象忙时新消息排队，M1 不提供 steer。
4. Codex 执行采用 `danger-full-access` 与 `approvalPolicy: never`，不实现执行审批弹窗。
5. M1 的 Web 页面和管理 HTTP API 不做登录鉴权，只监听本机地址。用户鉴权后续实现。
6. MCP 保留对象身份绑定，用于识别发送者与限制其目标私聊；这是协作协议身份，不是浏览器登录。
7. 每个对象固定一个原生 thread，重启只恢复该 thread，恢复失败显式报告。
8. 按官方文档直接开发，必要联调随实现进行，不安排独立前置可行性研究。

本阶段管理 HTTP API 未鉴权，不把它宣传成人类与本机进程之间的安全隔离。创建入口面向用户，MCP 不提供创建对象的能力。全权限执行也不提供对象之间的操作系统沙箱。

## 2. 完成后的使用链路

用户打开本地 Web，选择 Codex 的模型配置并创建对象；对象获得独立工作目录及固定 thread。用户发送私聊消息，看到排队、执行和完成状态；对象通过 MCP 回复，原生执行详情可展开查看。用户可停止对象，再显式恢复。重启 Isles 后历史仍在，继续输入沿用原 thread。

允许创建多个对象作为隔离验证，但本阶段围绕每个对象的独立私聊展开，不实现群聊、agent 互相私聊或自主创建对象。

## 3. 范围

本轮包括：

- 数据迁移、对象与私聊、消息及执行持久化。
- Codex 原生进程和 thread 生命周期。
- 每对象串行输入、持久停止状态、错误与恢复。
- 发送和读取所属私聊的最小 MCP 工具。
- Web 对象列表、创建表单、私聊、执行详情和停止/恢复操作。
- REST、SSE 及断线后的状态补读。
- 必要的原生用户问题回传；执行权限审批按 `never` 关闭。
- 开发自测和主 agent 的独立验收。

不在本轮实现：群聊、Kimi、Claude、steer、用户登录、对象改名/换模型/删除、独立共享产物系统、预算与复杂讨论策略。

## 5. 数据与接口边界

可按实现合并少量记录，但至少保存这些事实：

- 对象：稳定 ID、名称、harness、模型、工作目录、原生状态位置、thread ID、期望状态及观测状态。
- 私聊：稳定频道 ID 与所属对象。
- 消息：ID、频道序号、发送者、正文、回复关系、客户端去重标识。
- 投递：输入消息关联、排队/尝试/接受/结果不明等状态、关联原生 turn。
- 执行：对象与 thread、turn ID、状态、允许展示的文本/工具活动和错误。
- 原生用户问题：对象/turn/请求 ID、问题、回答和有效状态。
- 持久事件：供 SSE 补读的事件 ID、类型与必要数据。

建议 API 形状：

| 操作                     | 建议入口                                                     |
| ------------------------ | ------------------------------------------------------------ |
| 读取 Codex 环境/可用模型 | `GET /api/codex/status`、`GET /api/codex/models`             |
| 列出、创建、读取对象     | `GET/POST /api/objects`、`GET /api/objects/:id`              |
| 读取、发送私聊消息       | `GET/POST /api/objects/:id/messages`                         |
| 读取执行与事件           | 对象详情或独立 runs 接口；`GET /api/events`                  |
| 停止、恢复对象           | `POST /api/objects/:id/stop`、`POST /api/objects/:id/resume` |
| 回答原生用户问题         | 与具体请求 ID 绑定的响应入口                                 |

接口命名可按代码组织调整，业务语义固定。正式消息要先持久化再确认接收；提交消息、待投递记录和对应持久事件保持事务一致。数据库事务不跨越模型或网络等待。

## 6. Codex 接入

依据官方文档和本机版本生成的协议定义实现：

- 每个对象拥有可独立管理的原生进程/连接，完成一次初始化握手。
- 创建对象时调用一次 `thread/start`，保存原生 ID；CLI `0.158.0` 通过 `thread/inject_items` 注入一次启动规则使空 thread 落盘，不调用模型或产生用户 turn。
- 恢复用指定 ID 调用 `thread/resume`，不能改用最近会话、fork 或新建替代。
- 提交 `turn/start`，消费原生流式事件并关联当前执行。
- 停止通过原生 interrupt 和必要进程清理完成，不操作不属于本对象的进程。
- 明确设置全权限执行与 `never` 策略；不要加入未获选择的登录流程或审批默认值。
- 对原生用户提问提供可关联的 Web 回答；未知服务端请求给出明确结果，不能无限悬挂。

生成协议类型时只保留本次需要的部分或可复现的生成入口，避免引入整套无关生成文件。模型从实际可用配置选择，不把示例名称当成正式 model ID。

对象的工作目录与私有原生状态应独立。沿用本机可用的 Codex 认证，凭据不得进入日志、API 响应或 Git；不修改用户已有的全局配置。若原生状态隔离与现有认证/配置兼容性存在实质取舍，向主 agent 提出，不能静默共享私有 memory 或新建 session。

## 7. MCP、规则说明与发言

M1 只提供对象访问自身私聊所需的协作工具，例如：

- `send_message`：指定频道、正文、可选回复与去重标识。
- `read_messages`：读取自身私聊历史，支持有界分页。

对象身份由可信 MCP 连接绑定，正文不能伪造发送者。目标频道必须属于该对象；不提供创建对象、建群、邀请成员或联系其他对象的工具。

启动说明告诉对象自己的身份、工作目录、私聊 ID、消息封装规则，以及必须用 MCP 发布正式回复。跨轮次保持同一说明语义，不为每条消息重建 session。正式发言与原生最终输出不能重复写入聊天。

本阶段的 MCP 私聊能力用于回答用户所在的既有私聊；agent 主动发起其他私聊及其权限粒度留到 M2。

## 8. 调度、停止与恢复

- 对象忙时消息留在持久队列，不使用 steer，不并发发起同一 thread 的 turn。
- “停止对象”先持久化停止标志，再中断当前执行；其后新消息可保存但不自动运行。
- “恢复对象”由用户显式触发，恢复原 thread 后处理尚未接受的排队输入；创建后尚未聊天的对象也必须可恢复。
- 已取消或已被原生接受的输入不能自动当成新输入再次发送。
- 应用重启时重新读取期望状态和投递记录；原生是否接受无法确定的输入显示“待核对”，不盲目重试。
- 正常关闭时尚未结束的执行同样标记“待核对”，对象保持异常状态，显式恢复后才继续后续队列。
- 进程退出、thread 恢复失败、认证不可用等错误要在 Web 可见，避免空白页面或永久转圈。
- SSE 重连后按持久事件游标补读，或重新读取权威快照；不能仅靠临时文本增量恢复聊天。

原生进程启动不等于模型正在执行，turn 完成也不等于用户的工作目标已经验收完成。

## 9. Web 最小交付

- 对象列表与创建表单，清楚显示创建中、可用、运行中、已停止、异常等实际状态。
- 私聊历史与输入框，明确区分已保存、排队和执行。
- 正式消息区与执行详情分开，默认不把大量工具日志塞进聊天。
- 对象的停止/恢复按钮、原生用户问题的回答入口。
- 页面刷新、重连及服务重启后可恢复历史和状态。
- 采用现有 Vue/shadcn-vue 风格，保持桌面和窄屏可用，按钮不能只展示而无实际行为。

## 10. 开发自测与主 agent 验收

子 agent 完成实现与自测后停止改动，向主 agent 报告。主 agent 独立阅读关键路径，并按需重新运行或补充验证：

| 验收项       | 通过依据                                                                     |
| ------------ | ---------------------------------------------------------------------------- |
| 工程完整性   | 格式、lint、类型检查、服务测试和生产构建通过。                               |
| 数据持久化   | 迁移可重复执行；对象与正式消息重开后仍存在。                                 |
| 原生真实闭环 | 至少一个真实 Codex 对象完成用户消息 → 原生 turn → MCP 正式回复。             |
| 固定 session | 连续两轮及应用重启后原生 thread ID 保持一致。                                |
| 串行调度     | 忙碌时新输入排队；无同一对象的重叠 turn。                                    |
| 停止/恢复    | 停止后新消息不启动；显式恢复仍使用原 thread。                                |
| 发言归属     | 正式消息来自 MCP；无原生最终回复的重复消息，不能通过工具向别的对象私聊发言。 |
| 错误处理     | 恢复失败和结果不明可见，不自动创建新 thread 或盲目重投。                     |
| 用户提问     | 若原生发起问题，答案只回到仍有效的原请求。                                   |
| Web 链路     | 创建、私聊、状态、执行详情与停止/恢复可在浏览器实际操作。                    |
| 交付边界     | 未实现的 M2+ 功能没有伪装成已支持；未泄露凭据，未修改全局 Codex 配置。       |

自动化故障测试可以使用模拟 adapter；真实 Codex 冒烟应使用隔离测试数据和少量提示，不能用模拟结果代替原生接入验证。没有可用认证等外部条件时要如实报告，不得宣称全项通过。

## 11. 本轮协作约定

- 当前仅保留一个活动的 `gpt-6.1-sol / max` 实现子 agent，不再递归委派。
- 分支为 `feat/codex-m1`；保留已有未提交的文档调整。
- 子 agent 负责代码、必要依赖、迁移、测试及 README；主 agent 维护需求和计划并验收。
- 遇到会改变用户已确认行为、身份/会话语义或范围的问题，子 agent 先向主 agent 报告，再由主 agent 询问用户。
- 不提交、不推送、不创建 PR，除非用户另行授权。
